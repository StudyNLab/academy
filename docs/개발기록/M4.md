## 완료 기준 확인 (`docs/개발계획.md` M4)

| 할 일 | 완료 기준 | 결과 |
|---|---|---|

| 워터마크, 수강생 전용 표시 | 화면 확인 | ✅ 영상 위에 `닉네임 · #회원 번호 끝 6자리` 가 12초마다 자리를 옮긴다. 전체 화면에서도 보인다(영상이 아니라 감싼 상자를 키움). 오른쪽 클릭 · 다운로드 · PIP 막음. 미리보기 화면은 "🔒 수강생 전용 영상입니다", 학습 화면 캡션 "수강생 전용", 강의 상세 커리큘럼 "수강생 전용" |
| 인코딩 설정 (강의 영상용 저용량) | 화질 확인 + 비트레이트 목표 | ✅ 상한 1080p 1.5Mbps · 720p 0.9 · 360p 0.4 + CRF(23 · 24 · 26), 소리 AAC 96kbps. 실제 화면 녹화 실습 영상은 **1080p 평균 214kbps**(영상 + 소리), 원본 대비 SSIM 0.997 (글자가 또렷하다, 화면 확인). 움직임이 많은 영상도 상한을 넘지 않는다 |

함께 한 일 (M3 에서 넘김): 자체 서버 영상 재생 · 워터마크 ✅, **교재 그림 접근을 수강권으로 좁히기** ✅ — 공개 중인 버전의 그림은 무료 미리보기 범위에 나오는 것만 누구나, 나머지는 강의를 볼 수 있는 사람(수강권 · 운영자 · 그 과정 강사)만.

검사: `pnpm lint` · `typecheck` · `test`(core 64 · mail 4 · storage 5 · content 20 · web 90) · `build` 통과. 화면 흐름: `e2e/video.spec.ts`(올리기 ➔ 변환 ➔ 연결 ➔ 수강권 없으면 실패 ➔ 수강생 재생 · 워터마크 · 자막 · 시청 기록) 통과, M1 · M2 · M3 화면 흐름(`auth-flow` · `content-admin` · `learning`)도 다시 통과.

## 만든 것

| 영역 | 내용 |

| `apps/worker` | 영상 변환 작업: ffprobe ➔ ffmpeg 한 번으로 모든 화질 + AES-128 ➔ 실제 비트레이트를 재 대표 재생 목록 작성 ➔ 영상 버킷. 진행률 기록, 한 번에 하나, nice 10. 내릴 때 변환을 멈추고 1분 뒤 다시 |
| `apps/web` 서버 | 올리기 시작 · 조각 · 이어 올리기 · 마무리 · 다시 변환 · 자막 · 지우기 · 영상 자리 연결, 재생 정보(수강생 · 운영자), `/api/v1/media/check`(Caddy forward_auth), 키 서버 `/api/v1/hls/keys/{id}`, 개발용 `/media/...`, 교재 그림 권한 |
| `apps/web` 화면 | 과정 상세(AD-05): 자체 서버 영상 목록 · 올리기(16MB 조각 3개씩, 끊기면 다시) · 이어 올리기 · 자막 · 다시 변환 · 지우기, 영상 자리마다 "자체 서버 영상 고르기". 영상 보기 화면(화질별 비트레이트 · 재생). 학습 화면 플레이어(hls.js, 4분마다 토큰 갱신, 워터마크, 자막, 시청 기록 ➔ 영상 완료 조건) |

## 정한 것 · 바뀐 결정

| 무엇 | 정한 것 | 이유 |
|---|---|---|
| 올리기 경로 | 브라우저 ➔ **web** ➔ Garage 나눠 올리기 (설계는 브라우저 ➔ Garage 직접) | Garage 를 밖에 열지 않는다. 실오픈 때 S3 · R2 로 가면 미리 서명한 주소로 바꾼다 (`server/videos.ts` 만) |
| 변환 결과 버킷 | 영상 전용 `aionit-media` 를 따로 두고 이것만 Garage 웹 공개 | Garage 웹 주소는 버킷째 인증 없이 내준다. 교재 원본 · 첨부가 있는 `aionit` 은 열지 않는다. 내부망에서 조각을 받아도 암호화돼 있고 키는 web 이 준다 |
| 변환 결과 백업 | 하지 않는다 (원본은 `aionit` 버킷이라 매일 백업됨) | 원본으로 다시 만들 수 있다 |
| 영상 소유 | 강사가 아니라 **과정**에 묶음 (`video_assets.course_id`) | 키 서버가 그 과정의 수강권 하나로 판단 (기술설계 3.2 "판단 함수 하나") |
| 토큰 전달 | 주소가 아니라 머리글 `X-Media-Token` | 기록 · 공유 주소에 남지 않는다. Caddy forward_auth 가 그대로 web 에 넘긴다 |
| 조각 확인 | DB 를 보지 않고 서명 · 만료 · 영상 일치만 | 조각 요청이 많다. 수강권은 토큰 발급(4분마다)과 키 요청 때 다시 본다 |
| 비밀값 | 새 비밀값을 두지 않고 `BETTER_AUTH_SECRET` 에서 쓰임마다 키를 뽑음(HKDF) | 운영할 비밀값을 늘리지 않는다. HLS 키는 키 번호와 함께 저장해 나중에 바꿀 수 있다 |
| 변환 순서 | 한 번에 하나 | app VM 2 vCPU 에서 web 과 같이 돈다 |
| 다시 변환 중 | 그 영상은 재생되지 않는다 (끝나면 다시) | 키가 바뀌므로 예전 조각과 섞이지 않게 |
| 영상 완료 조건 | 변환이 끝난 자체 서버 영상도 센다 (90%) | M3 에서 "재생할 수 있는 영상만" 으로 정한 규칙 그대로 |
| 교재 그림 캐시 | 수강권으로 본 그림은 `private`(사람마다), 미리보기 그림만 `public` | 공유 캐시에 수강생 전용 그림이 남지 않게 |

## 테스트로 찾은 문제 (고침)

- Caddy 가 지시어를 자기 순서로 돌려 `uri strip_prefix` 가 `forward_auth` 보다 먼저 실행 ➔ 확인할 주소가 바뀌어 404 ➔ `route` 로 적은 차례 고정
- 배포 스크립트가 Caddyfile 만 바뀐 것을 모르고 Caddy 를 다시 띄우지 않음 ➔ 바뀌었으면 검사 후 다시 띄움
- 영상 올리기 버튼 이름이 교재 올리기 버튼과 같아 M2 화면 흐름 테스트가 헷갈림 ➔ "영상 올리기"
- 미리보기 그림 경로를 뽑는 정규식이 깨져 그림 이름이 잘림 ➔ 고치고 테스트 추가

- 실습 영상 "CH01 실습 1 시연" 은 테스트 서버에 **올려 둔 채(연결 안 함)** 둔다 — 교재에 `ch01_lab01` 자리가 생기면 바로 연결할 수 있다. 1시간 시험 영상은 지웠다
- 시험 계정은 탈퇴, 첫 시도에서 2단계 인증 비밀값을 잃은 시험 운영자 1명은 역할 회수 + 정지
