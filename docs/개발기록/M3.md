## 정한 것 · 바뀐 결정

| 무엇 | 정한 것 | 이유 |
|---|---|---|
| 교재 완료 "최소 기준(글 분량)" | 글자 수 ÷ 25 초, 1분 ~ 15분 (1분에 1,500자 훑어 읽는 속도) | 화면상세기획에 값이 없었다. `packages/core` 한 곳에서 바꾼다 |
| 영상 완료 조건에 드는 영상 | 지금 연결돼 재생할 수 있는 영상만 (유튜브). 연결 안 된 자리는 빼고 센다 | 볼 수 없는 영상 때문에 완료가 막히지 않게. 자체 서버 영상은 M4 |
| 한 번 완료한 챕터 | 되돌리지 않는다 (체크를 풀거나 새 버전이 나와도) | 진도가 줄어드는 것은 혼란만 준다 |
| `chapter_progress` 필드 | `videos_done` · `checks_done_count` 대신 `text_seconds` · `reached_end_at` | 영상 · 체크는 원래 표에서 다시 세는 편이 어긋나지 않는다. 교재 머문 시간은 따로 쌓아야 한다 |
| 첫 이용(`first_used_at`) | 첫 영상 재생 또는 첫 첨부 받기 | 데이터모델 3.8 그대로. 교재를 읽기만 한 것은 "이용"으로 치지 않는다 — 환불 규정(M5) 정할 때 다시 본다 |
| 운영자 발급 기간 | "n일" = 오늘부터 n일 뒤 그날 끝(KST 자정)까지 | 화면에 날짜로 보여 줄 때 하루가 덜 보이지 않게 |
| 읽은 위치 저장 | 화면을 열기만 하고 떠나면 저장하지 않는다. 끝까지 내려오면 마지막 Section 으로 친다 | 시험 중 발견: 열었다 닫기만 해도 "마지막으로 읽은 곳"이 맨 위로 덮였다 |
| 화면을 떠날 때 저장 | `sendBeacon` 대신 `fetch(keepalive)` | 같은 Origin 확인 · JSON 형식을 그대로 쓴다 |

## 테스트로 찾은 문제 (고침)

- 열기만 하고 떠나도 읽은 위치가 맨 위로 저장돼 "마지막으로 읽은 곳"이 사라짐 ➔ 움직였을 때만 저장, 서버도 빈 위치로 덮지 않음
- 짧은 챕터는 끝까지 내려도 마지막 Section 이 위로 올라오지 않아 읽은 위치가 첫 Section 에 머묾 ➔ 끝에 닿으면 마지막 Section
- 챕터 라벨이 교재 표지와 겹쳐 두 번 보임 ➔ 표지 것만
- 챕터 끝 요약이 본문과 다른 선에 맞춰짐 ➔ 본문과 같은 왼쪽 선
- 유튜브 새 플레이어는 재생 버튼 이름이 바뀌어 화면 흐름 테스트가 못 찾음 ➔ 접근성 이름("재생")으로 찾는다
