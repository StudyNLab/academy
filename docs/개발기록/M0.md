# M0 개발 기록 · 뼈대 · 개발 환경 · 배포

- 기간: 2026-11-03 ~ 2026-11-04
- 브랜치: `m0-scaffold`

## 완료 기준 확인 (`docs/개발계획.md` M0)

| 기준 | 결과 |
|---|---|
| `pnpm lint` · `test` · `build` 통과 | ✅ (typecheck · Prettier 포함) |
| 명령 하나로 개발 환경 | ✅ `pnpm dev:tunnel` + 개발 VM(PostgreSQL · Garage · Mailpit). 노트북에는 Docker 를 두지 않기로 함 |
| 마이그레이션 적용 | ✅ 개발 DB · 테스트 DB 모두 `0000` 적용. 되돌리기는 백업 복구 / 고치는 마이그레이션으로 (Drizzle 은 되돌리기 마이그레이션 없음) |
| 홈 화면이 디자인 시스템대로 (라이트 · 다크) | ✅ 색 · 글꼴 값을 브라우저에서 직접 확인, 모바일 폭 가로 스크롤 없음 |
| 두 VM 에 올라가 내부망으로 통신 | ✅ app ➔ data 5432 · 3900 열림, dev ➔ data 막힘 |
| 명령 하나로 배포 · 되돌리기 | ✅ `deploy.sh`, `deploy.sh --rollback` (두 번 배포 후 되돌리기 시험) |
| 백업이 생기고 그것으로 복구 | ✅ 호스트 G: 로 복사 · 체크섬 검증, 새 DB 로 복구해 테이블 수 일치 |

## 바뀐 결정

| 원래 | 바뀜 | 이유 |
|---|---|---|
| 파일 저장소 MinIO | **Garage** | MinIO 무료판 이미지 배포 중단 · 유지보수 모드 (2025-10) |
| 노트북에 Docker | **개발 VM(Academy-dev)** | 노트북을 가볍게, 서버와 같은 Ubuntu, 항상 켜짐 |
| data VM 에 이미지 레지스트리 | **개발 VM 에 보관소(2026-11-05).** 처음에는 `docker save | docker load` 로 직접 옮겼다 | 개발 VM 은 내부망과 분리되어 있어, 배포하는 동안만 노트북을 거치는 SSH 터널로 앱 VM 이 받아 간다. worker 이미지가 1.8GB 로 커져서 통째로 옮기는 것이 배포 시간의 큰 몫이 됐다 |
| 서버에서 빌드하지 않음 | 그대로. 빌드는 개발 VM 에서 | |
| TypeScript 7 | **6.0.3** | typescript-eslint 가 7 미지원 |
| 최신 패키지 | 나온 지 하루 이상 지난 버전만 (pnpm 공급망 규칙, 예외 두지 않음) | vitest 5.1.0 · postgres 4.0 대신 5.0.5 · 3.4.9 |
