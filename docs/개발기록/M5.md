## 정한 것 · 바뀐 결정

| 무엇 | 정한 것 | 이유 |
|---|---|---|
| 토스 연동 방식 | **결제위젯**(SDK v2) | 화면상세기획 C-01 이 결제위젯. 그리고 토스 문서의 "API 개별 연동" 공개 테스트 키(`test_ck_…`)는 토스가 `UNAUTHORIZED_KEY` 로 거부하고, 결제위젯 문서용 테스트 키(`test_gck_docs_…` / `test_gsk_docs_…`)는 살아 있다. 그래서 운영자 키 없이 공개 테스트 키로 개발 · 테스트 서버를 돌린다 |
| 화면 흐름 테스트의 결제 | 개발 서버 가짜 결제(`TOSS_FAKE=1`, 운영 빌드에서는 꺼짐) | 토스 **테스트 모드도 카드 결제는 실제 카드사 본인 인증 화면**(KB · 하나 등 카드사 페이지)을 거친다. 토스페이 · 페이코 등도 실제 계정 로그인. 자동화할 수 없고 Claude 가 카드 정보를 넣을 수도 없다 |
| 환불 금액의 기준 | 수강생이 **요청한 날**의 계산. 운영자 화면에는 오늘 다시 계산한 값도 참고로 | 처리가 늦어져 7일 · 1/3 경계를 넘으면 수강생이 손해를 본다 |
| 운영자가 금액을 바꿀 때 | 이유 필수, 남은 결제 금액 이하 | 규정 밖 처리의 근거를 남긴다 |
| 무제한 상품의 기간 기준 | 1년(365일)으로 센다 | 규정 표가 기간 비율을 쓰는데 무제한이면 계산할 수 없다. 환불 정책 초안에 적음 |
| 연장권 환불 | 늘어난 기간 시작 전이면 전액, 시작 뒤에는 늘어난 기간의 지난 비율로 같은 단계 (진도율은 보지 않음) | 진도는 원래 기간에 쌓인 것이라 |
| 연장 방식 | 새 수강권을 만들지 않고 기존 단건 수강권(가장 늦게 끝나는 것)의 끝나는 날을 늘림. 연장 전 · 뒤 날짜는 `order_items.extension` 에 | "만료일이 늘어난다" 그대로. 화면 · 알림이 수강권 하나만 보면 된다 |
| 이미 수강 중 | 단건 · 운영자 발급 수강권으로 보고 있으면 주문서를 만들지 않음. 구독 수강권만 있으면 살 수 있음 | 데이터모델 D3 (구독이 끝나도 단건으로 계속) |
| 주문서 재사용 | 같은 상품 · 같은 가격 버전의 주문서가 5분 이상 남아 있으면 그것을 씀 | 새로고침 · 뒤로 가기로 주문이 쌓이지 않게 |
| 구독자 할인 판단 | 지금 유효한 구독 수강권(`subscription_catalog`)이 있으면 구독자 | 구독(M6) 전에도 같은 규칙. M6 에서 구독이 수강권을 만든다 |
| 이용("첫 이용") | M3 그대로: 수강생 전용 영상 첫 재생 또는 첫 실습 파일 받기. 교재를 읽기만 한 것은 이용이 아님 | M3 에서 M5 로 미룬 결정. 환불 정책 초안에 적음 |
| 토스 고객 키 | 회원 id 가 아니라 앱 비밀값으로 만든 HMAC | 토스 권고 (유추할 수 없는 값) |

## 테스트로 찾은 문제 (고침)

- 토스 문서의 API 개별 연동 공개 테스트 키가 거부됨(`UNAUTHORIZED_KEY`) ➔ 결제위젯 + 결제위젯 문서용 키로 바꿈
- 개발 모드에서 화면 효과가 두 번 돌아 결제위젯을 두 번 그리려다 "하나의 결제수단 위젯만" 오류 ➔ 한 번만 그림
- 강의 상세의 구매 버튼이 좁은 화면 막대와 이름이 같아 화면 흐름 테스트가 헷갈림 ➔ 테스트에서 카드 쪽을 고름

## 테스트 서버 확인

`9ff5796` 배포 (배포 전 DB 백업 `pre-deploy-9ff5796`, 마이그레이션 0006 적용, app VM `.env` 에 `TOSS_CLIENT_KEY` · `TOSS_SECRET_KEY` 추가 — 토스 문서용 공개 테스트 키). 시험 운영자(`grant-role` + 2단계 인증) · 시험 수강생으로 실제 Caddy · 토스 테스트 환경에서:

- 운영자 화면에서 실제 교재 과정 "AI Agent 개발 · 초급" 에 상품 2개를 만듦: **1년 59,000원**, **연장권 90일 17,700원** (운영자가 가격을 바꾸거나 판매를 멈추면 된다)
- 강의 상세 구매 카드 59,000원 ➔ 구매하기 ➔ 주문서(공급가액 53,636 · 부가세 5,364, 환불 규정 `2026-11-04-draft`) ➔ **토스 결제위젯이 "테스트 환경" 으로 뜸** ➔ 카드 · 일시불 ➔ 결제하기 ➔ **토스 결제창(KB국민카드 인증 화면)까지 열림**
- 결제창을 마치지 않고 성공 주소로 바로 가면(위조) 서버가 토스 승인 API 를 불러 토스가 거절(`결제 시간이 만료되어 결제 진행 데이터가 존재하지 않습니다`) ➔ app VM 에서 토스 API · 비밀 키 인증이 된다. 금액을 바꾸면 토스를 부르지 않고 거절
- 웹훅 주소 `POST /api/v1/payments/toss/webhook` 응답 (모르는 결제 ➔ `unknown payment`), 개발용 가짜 결제 주소는 운영 빌드에서 404
- **실제 카드 승인 ➔ 수강권 ➔ 환불 요청 ➔ 운영자 처리(토스 취소)**: 토스 테스트 모드도 카드사 본인 인증(실제 카드, 돈은 나가지 않음)을 거쳐야 해서 운영자 확인을 기다림 (아래)
