훈련에서 찾은 것: ① sha256 경로 (위), ② DB 역할은 `pg_dump` 에 없다 ➔ 설정 백업에 `pg_dumpall --globals-only` 를 넣고 복구 스크립트가 먼저 넣게 함 (0012 의 `aionit_app` 을 서버에서 켜면 꼭 필요), ③ base0_clean 은 켠 채 찍은 스냅샷이라 복제가 "저장됨" 상태로 생긴다 ➔ `discardstate` 후 설정, ④ 실제 복구가 아니라 훈련일 때는 compose 의 `172.30.0.20:` 을 `127.0.0.1:` 로 바꿔야 뜬다.

app VM 은 복구 훈련을 하지 않았다: 상태가 없고(DB · 파일은 data VM), 이미지는 `deploy.sh --force` 로 다시 놓는다. app VM 의 `.env` · Caddy 인증서는 아래처럼 매일 받아 두고, 개인키로 풀리는 것(파일 6개)을 확인했다.

**app VM 설정 받기** (14:55, 운영자 허락): data VM 전용 키를 app VM `authorized_keys` 에 강제 명령(`config-backup.sh` 만, `from="172.30.0.20"`, 포워딩 · 터미널 금지)으로 등록. 확인: 받기 2초 · 6KB, 다른 명령을 보내도 같은 암호화 묶음만 나옴, 포트 포워딩은 "administratively prohibited". 매일 백업 전체(DB · 파일 두 버킷 · 설정 둘) 2초.
