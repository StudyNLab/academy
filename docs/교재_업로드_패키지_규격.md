## 1. 목적과 원칙

교재를 온라인아카데미 사이트에 올릴 때 **완성된 HTML 페이지가 아니라 "본문 조각 + 이미지 + 목차 정보"를 묶은 패키지**로 올린다.

| 원칙 | 내용 |
|---|---|
| 변환 규칙은 한 곳 | Markdown ➔ HTML 변환 규칙은 교재 세션의 변환 도구에만 둔다. 플랫폼은 다시 변환하지 않는다 |
| 디자인·동작은 플랫폼 | 상단 막대, 목차, 그림 크게 보기, 코드 복사 동작, 다크 모드, 반응형은 플랫폼이 한 벌로 맡는다. 패키지에는 CSS·JS를 넣지 않는다 |
| 패키지는 콘텐츠만 | 가격, 무료 미리보기 여부, 공개 일정 같은 판매 정보는 넣지 않는다. 플랫폼 관리자 화면에서 정한다 |
| 이미지는 따로 | 이미지는 HTML 안에 넣지 않는다(base64 금지). 플랫폼이 WebP 변환, 크기별 축소, 지연 로딩을 한다 |
| 안전 | 플랫폼은 허용 목록(3.5)에 없는 태그·속성·class를 지운다. 스크립트는 들어올 수 없다 |

## 2. 패키지 구조

과정(교재) 하나 = zip 파일 하나.

```text
<course_id>_v<version>.zip
├─ course.json                  과정 정보와 챕터 순서
├─ images/                      과정 전체가 함께 쓰는 그림 (2_교재/images 와 같음)
│   ├─ fig1-01.png
│   └─ ...
└─ chapters/
    ├─ 01_로그관리_기본_개념/
    │   ├─ content.html          본문 조각 (3장)
    │   ├─ manifest.json         챕터 목차·그림·실습 정보 (2.2)
    │   └─ source.md             Markdown 원본 그대로 (검색·재변환용)
    └─ 02_.../
```

- 파일 이름은 UTF-8. 폴더 이름은 원본 MD 파일 이름(확장자 제외)을 그대로 쓴다.
- zip 안에 위 목록 밖의 파일(`.git`, `__pycache__`, 임시 파일)은 넣지 않는다. 플랫폼은 목록 밖의 파일을 무시한다.

### 2.1 course.json

```json
{
  "schema": "academy-course/0.2",
  "course_id": "linux-log-management",
  "title": "리눅스 로그 관리",
  "field": "리눅스 서버 운영관리",
  "version": "1.0.0",
  "built_at": "2026-11-03T15:00:00+09:00",
  "generator": "build_academy_html.py (제작방식 0.6.0)",
  "chapters": [
    { "chapter_id": "ch00", "dir": "00_교재개요", "title": "교재 개요" },
    { "chapter_id": "ch01", "dir": "01_로그관리_기본_개념", "title": "CHAPTER 1. 로그관리 기본 개념" }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `schema` | ✅ | 이 규격의 버전. 지금은 `academy-course/0.2` |
| `course_id` | ✅ | 영문 소문자·숫자·`-`. **한 번 정하면 바꾸지 않는다.** 플랫폼은 이 값으로 같은 과정인지 판단한다 (판매 상품, 수강권, 진도가 여기에 묶인다) |
| `title`, `field` | ✅ | 과정 이름, 분야 이름 |
| `version` | ✅ | 교재 버전 (예: `1.0.0`). 같은 버전을 다시 올리면 덮어쓴다 |
| `built_at`, `generator` | ✅ | 언제, 어떤 도구 버전으로 만들었는지 |
| `chapters` | ✅ | 사이트에 보일 순서대로. `chapter_id` 는 과정 안에서 고유하며 **바꾸지 않는다** (진도가 여기에 묶인다) |

### 2.2 manifest.json (챕터마다)

```json
{
  "schema": "academy-chapter/0.2",
  "chapter_id": "ch01",
  "label": "CHAPTER 1",
  "title": "로그관리 기본 개념",
  "source": "01_로그관리_기본_개념.md",
  "source_sha256": "<원본 MD의 SHA-256>",
  "toc": [
    { "level": 1, "id": "sec-1", "title": "1. 로그란 무엇인가", "lab": false },
    { "level": 2, "id": "sec-1-3", "title": "1.1 로그의 역할", "lab": false },
    { "level": 1, "id": "sec-4", "title": "실습 1: journalctl 로 로그 보기", "lab": true }
  ],
  "images": [
    { "path": "images/fig1-01.png", "alt": "그림 1-1. Rocky Linux 9의 로그 흐름", "width": 1440, "height": 900 }
  ],
  "videos": [
    { "key": "ch01_main",  "kind": "main", "title": "CHAPTER 1 강의" },
    { "key": "ch01_lab01", "kind": "lab",  "title": "실습 1 시연", "section_id": "sec-4" },
    { "key": "ch01_extra01", "kind": "extra", "title": "journald 저장 구조 보충 설명", "section_id": "sec-2" }
  ],
  "labs": [
    {
      "section_id": "sec-4",
      "title": "실습 1: journalctl 로 로그 보기",
      "self_check": [
        { "id": "c1", "text": "journalctl -u sshd 로 sshd 로그가 보인다" }
      ]
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `toc` | ✅ | 지금 도구가 만드는 목차(`toc` 목록)와 같다. `id` 는 content.html 안의 요소 id 와 반드시 같아야 한다. 플랫폼은 이 목록으로 왼쪽 목차와 "어디까지 읽었는지"를 만든다 |
| `images` | ✅ | content.html 이 쓰는 그림 전부. `width`·`height` 는 원본 픽셀 크기 (화면이 밀리지 않게 자리를 미리 잡는 데 쓴다) |
| `videos` | 선택 | 이 챕터의 영상 자리 (3.4). `kind`: `main`(맨 위 챕터 영상, 챕터에 0~1개) · `lab`(실습 시연) · `extra`(추가 설명). `main` 이 아닌 것은 content.html 안의 자리와 1:1 로 맞아야 한다 |
| `labs` | 선택 | 실습 Section 목록. `self_check` 는 **수강생이 스스로 체크하는 평가 기준**이다. 플랫폼은 항목마다 체크 상자를 보여주고 체크 상태를 저장한다 |

> **결정 필요 (교재 세션)**: 평가 기준 항목을 원본 MD에 어떻게 적을지(예: 실습 Section 끝의 `> **✅ 스스로 확인**` 목록) 정한 뒤, 도구가 그것을 읽어 `self_check` 에 넣는다. 정하기 전까지 `labs` 는 비워도 된다.

## 3. content.html (본문 조각)

### 3.1 무엇을 넣고 무엇을 빼나

지금 `build()` 가 만드는 `PAGE` 에서 **`<main>` 안의 내용(`{body}`)만** 넣는다.

| 넣는다 | 뺀다 (플랫폼이 맡음) |
|---|---|
| `header.cover`, `section.goals`, `div.flow`, `section.sec ...` 와 그 안의 모든 내용 | `<!DOCTYPE>`, `<html>`, `<head>`, `<body>`, `<meta>`, `<title>` |
| | `<style>`, `<link>`(글꼴 포함), `<script>` |
| | `header.topbar`, `nav.toc`, `div#zoom-view` |
| | 원본 안내 주석 `<!-- 원본: ... -->` |

### 3.2 그림

- `src` 는 패키지 루트 기준 상대 경로로 쓴다: `images/fig1-01.png` (지금 도구의 `../images/` 가 아니다).
- `--embed`(base64) 는 쓰지 않는다. `data:` 주소는 플랫폼이 지운다.
- 형식은 PNG, JPEG, WebP. **SVG는 받지 않는다** (안에 스크립트를 넣을 수 있다). 구조도는 지금처럼 PNG로 렌더링해서 넣는다.
- `<img>` 에 `width`·`height` 속성을 넣는다 (manifest 의 값과 같게). `loading="lazy"` 는 있어도 되고 없어도 된다 (플랫폼이 붙인다).

### 3.4 영상 자리

교재에는 **영상이 들어갈 자리와 이름(key)만** 표시한다. 실제 영상(유튜브 주소 또는 자체 서버 영상), 무료/유료 여부, 자막은 플랫폼 관리자 화면(AD-05)에서 key 에 연결한다. 그래서 영상을 바꾸거나 유튜브 ➔ 자체 서버로 옮겨도 교재를 다시 올리지 않는다.

**content.html 안의 표시** (교재 사이사이의 영상만. 맨 위 챕터 영상은 manifest 에만 적는다)

```html
<div class="video-slot" data-video="ch01_lab01" data-kind="lab"><p class="video-title">실습 1 시연</p></div>
```

- `key` 형식: 영문 소문자·숫자·`_`. 과정 안에서 고유하며 **바꾸지 않는다** (영상 연결과 시청 진도가 key 에 묶인다).
- 이름 규칙(권장): `ch<챕터>_main`, `ch<챕터>_lab<번호>`, `ch<챕터>_extra<번호>`. 지금 `2_교재/실습영상` 의 `ch01_lab01_v020.mp4` 는 key `ch01_lab01` 에 연결한다 (버전 꼬리 `_v020` 는 key 에 넣지 않는다).
- 플랫폼은 이 `div` 를 영상 플레이어로 바꾼다. 연결된 영상이 아직 없으면 수강생에게는 보이지 않고, 관리자 미리보기에만 "영상 연결 필요"로 보인다.

> **결정 필요 (교재 세션)**: 원본 MD에 영상 자리를 적는 표기. 예: 지금의 강조 박스 표기에 맞춰 `> **🎬 영상** ch01_lab01 실습 1 시연` 한 줄. 도구가 이것을 위 `div` 로 바꾸고 manifest `videos` 에 넣는다. 챕터 영상은 MD 맨 위(CHAPTER 제목 아래)에 같은 표기로 `ch01_main` 을 적으면 `kind: main` 으로 본다.

### 3.5 허용 목록

플랫폼은 아래에 없는 것을 지운다. `data-` 속성은 `div.video-slot` 의 두 개만 허용한다. 새 표현이 필요하면 이 표를 먼저 고친다 (양쪽이 같이 바꿔야 한다).

**태그**

`section, header, div, span, p, h1, h2, h3, h4, ul, ol, li, table, thead, tbody, tr, th, td, figure, figcaption, img, pre, code, a, strong, b, em, i, br, details, summary, button, blockquote, hr, sup, sub, kbd`

**속성**

| 속성 | 쓸 수 있는 곳 |
|---|---|
| `class` | 모든 태그 (값은 아래 class 목록만) |
| `id` | `section`, `h2` (형식 `sec-숫자`, `sec-숫자-숫자`) |
| `src`, `alt`, `width`, `height`, `loading` | `img` |
| `href` | `a`. `#sec-...`(본문 안 이동) 또는 `https://...` 만. 외부 주소는 플랫폼이 새 창 + `rel="noopener noreferrer"` 로 바꾼다 |
| `type="button"` | `button` (class `copy` 만) |
| `colspan`, `rowspan` | `th`, `td` |
| `data-video`, `data-kind` | `div.video-slot` 만 (3.4) |
| `open` | `details` |

`style` 속성과 `on...` 이벤트 속성은 모두 지운다.

**class** (지금 도구와 `academy.css` 에서 쓰는 이름)

| 구역 | class |
|---|---|
| 표지·흐름 | `cover`, `label`, `goals`, `flow`, `flow-title`, `lab` |
| Section | `sec`, `lab`, `summary`, `num` |
| 강조 박스 | `box`, `warn`, `tip`, `prac`, `box-title` |
| 정의·코드 읽기 | `def`, `code-sec`, `core`, `basic`, `print` |
| 코드 | `code`, `run`, `term`, `key`, `fold`, `text`, `plain`, `code-head`, `tag`, `where`, `lang`, `copy`, `open`, `hl`, `numbered`, `line`, `dim`, `ln`, `prompt`, `cmd` |
| 그림·표 | `fig`, `tbl`, `tbl-wrap` |
| 영상 자리 | `video-slot`, `video-title` |
| 문법 색 (pygments) | `pre.hl code` 안에서만, pygments 짧은 토큰 이름 (`k`, `kn`, `n`, `nf`, `s1`, `s2`, `c1`, `o`, `p`, `mi` 등. 형식: 영문 1~3자 + 숫자 0~1자) |

## 5. 다시 올릴 때 (교재 수정)

- 같은 `course_id` 로 올리면 **새 버전**으로 들어간다. 관리자가 미리보기로 확인한 뒤 공개하면 그때부터 수강생에게 보인다.
- 진도는 `chapter_id` 와 Section `id` 에 묶인다.
  - `chapter_id` 는 바꾸지 않는다.
  - Section `id`(`sec-1`, `sec-2` ...)는 지금 순서 번호라서, 중간에 Section 을 넣으면 뒤의 id 가 밀린다. 이 경우 그 챕터의 "마지막으로 읽은 위치"만 앞쪽으로 어긋나고 다른 문제는 없다. 나중에 고정 id(예: 원본 MD 제목 기반)로 바꿀 수 있다.
- `source_sha256` 이 같으면 플랫폼은 그 챕터를 바뀌지 않은 것으로 보고 건너뛴다.

## 6. 변환 도구에 필요한 변경 (교재 세션 작업)

`build_academy_html.py` 에 내보내기 옵션 하나를 추가한다. 변환 규칙(`convert_code`, `convert_blockquote`, Section 나누기 등)은 그대로 쓴다.

```text
python ../../../제작방식/도구/academy_html/build_academy_html.py --export <내보낼 폴더> [--course-id linux-log-management] [--version 1.0.0]
```

1. `PAGE` 로 감싸지 않고 `str(out)`(본문)만 `chapters/<이름>/content.html` 로 쓴다.
2. 그림 `src` 를 `../images/` 대신 `images/` 로 쓰고, `width`·`height` 를 넣는다. `--embed` 는 `--export` 와 함께 쓰지 않는다.
3. 이미 만든 `toc` 목록과 그림 목록으로 `manifest.json` 을 쓴다.
4. 원본 MD를 `source.md` 로 복사하고 SHA-256을 계산한다.
5. 과정 전체에 대해 `course.json`, `images/` 를 쓰고 zip 으로 묶는다.
6. 영상 자리 표기(3.4)를 `div.video-slot` 으로 바꾸고 manifest `videos` 에 넣는다.
7. (권장) 3.5 허용 목록으로 결과를 검사하는 확인 단계를 둔다. 허용 목록 밖의 태그·class가 나오면 경고한다.

## 7. 플랫폼이 하는 일 (참고)

1. zip 구조와 `schema` 확인 ➔ 2. content.html 을 허용 목록으로 정리(sanitize) ➔ 3. 그림을 WebP·크기별로 변환하고 `src` 를 플랫폼 주소로 바꿈 ➔ 4. 새 버전으로 저장(비공개) ➔ 5. 관리자 미리보기 ➔ 6. 공개

- 업로드 방법: 처음에는 관리자 화면에서 zip 업로드. 나중에 명령 한 줄로 올리는 업로드 도구(API 토큰 사용)를 만든다.
- 화면: `academy.css`·`academy.js` 의 디자인과 동작(목차 현재 위치, 읽은 정도, 코드 복사, 그림 크게 보기, 접은 코드)을 플랫폼으로 옮기고, 읽은 위치 저장·다크 모드·워터마크를 더한다.
