# Figma AI 요청 프롬프트 — 디자인은 Figma AI 가 정한다

- 작성: 2026-11-04 (같은 날 고침)
- 목적: 화면에 **무엇이 들어가는지(내용 · 기능)** 만 알려 주고, **색 · 글꼴 · 배치 · 스타일은 Figma AI 가 제안**하게 한다. 우리 임시 디자인과 다른 눈으로 본 결과를 받는 것이 목적이다.
- 고친 이유: 처음 버전은 색 · 글꼴 · 크기 · 선 · 카드 금지까지 다 정해 두어서, 결과가 지금 임시 디자인과 똑같이 나왔다. 그래서 디자인 지시를 전부 뺐다.

---

## 0. 쓰는 법

| 도구 | 위치 | 받는 것 |
|---|---|---|
| **First Draft** | Figma Design 파일 → 아래 툴바 Actions(✦) → First Draft | 고칠 수 있는 Figma 레이어 — 디자이너에게 넘기기 좋음 |
| **Figma Make** | figma.com → Make 새로 만들기 | 눌러 볼 수 있는 시제품 |

1. **① 공통 프롬프트**를 먼저 넣는다. Figma AI 가 디자인 방향을 몇 가지 제안하게 되어 있다.
2. 마음에 드는 방향을 고르고, **② 화면별 프롬프트**를 한 화면씩 넣는다.
3. 더 보고 싶으면 **③ 이어서 쓰는 말**을 쓴다.

## ① 공통 프롬프트 (맨 처음 한 번)

```
한국의 온라인 IT 교육 서비스 화면을 디자인해 줘. 색, 글꼴, 배치, 스타일은 네가 가장 좋다고 생각하는 대로 정해 줘.

[서비스]
- 이름: AIONIT (아이오닛). "AI on IT" — IT 의 바탕 위에 AI 를 얹는다는 뜻.
- 가르치는 것: IT 인프라(리눅스 서버, 네트워크), 정보보안(보안 관제, 침해 대응), AI(LLM, AI Agent, 업무 자동화).
- 배우는 사람: 한국의 직장인, IT 실무자, 취업 준비생. 개인이 돈을 내고 듣는다.
- 파는 방법: 강의 하나씩 구매, 또는 월/연 구독. 여러 명의 현업 강사가 강의를 올린다.
- 다른 곳과 다른 점: 영상만 보는 게 아니라, 책처럼 다시 펼쳐 보는 교재와 실제 서버에서 해 보는 실습이 함께 있다. 실습마다 "해냈는지 스스로 확인하는 체크리스트"가 있다.
- 로고는 아직 없다. 로고 자리에는 "AIONIT" 글자만 두고, 로고를 새로 그리지는 마.

[화면 목록]
홈, 강의 목록, 강의 상세, 학습 화면, 로그인 · 회원가입, 마이페이지, 그리고 모바일 버전.

먼저 이 서비스에 어울리는 디자인 방향을 서로 다르게 3가지 제안해 줘. 방향마다 홈 화면 첫 부분을 하나씩 보여 주고, 왜 그렇게 했는지 한두 줄로 설명해 줘.
```

## ② 화면별 프롬프트

방향을 고른 뒤 `"2번 방향으로"` 처럼 붙여서 한 화면씩 요청한다. 아래에는 **들어갈 내용과 기능만** 있다. 어떻게 배치하고 꾸밀지는 Figma AI 가 정한다.

### 홈

```
고른 방향으로 홈 화면 전체를 만들어 줘. 들어갈 내용:
- 메뉴: 강의, 구독, 강사, 로그인, 무료로 시작하기
- 서비스 한 줄 소개: "IT의 바탕 위에, AI를 켜다." / "인프라 · 보안 · AI를 현업 강사에게. 영상으로 개념을 잡고, 다시 펼쳐 보는 교재로 정리하고, 실습 기준으로 스스로 확인합니다."
- 주요 행동: 강의 보기, 구독 알아보기
- 분야 3개: 인프라(리눅스 서버 운영, 로그 관리, 네트워크), 보안(보안 관제, SIEM, 침해 대응), AI(LLM API, AI Agent, 업무 자동화)
- 지금 열린 강의 몇 개: 강의 이름, 한 줄 소개, 강사, 분야 · 수준, 구성(예: 6장 · 실습 12), 구독 포함인지 / 단건 가격. 예: "AI Agent 개발 · 초급 — LLM API 호출부터 도구 호출, Agent 루프, 대화 기억까지"
- 공부하는 방법: 영상으로 개념 → 교재로 정리 → 실습으로 확인(체크리스트)
- 강사 소개 몇 명
- 구독 안내: 월간 / 연간 요금, 구독하면 구독 포함 강의 전부 수강, 해지는 마이페이지에서 언제든
- 강사 모집: "현업의 지식을 강의로 만드세요"
- 바닥글: 사업자 정보, 공지, 자주 묻는 질문, 이용약관, 개인정보처리방침, 환불 정책
값이 없는 곳은 [가격], [강사 이름]처럼 대괄호로 둬.
```

### 강의 목록

```
같은 방향으로 강의 목록 화면을 만들어 줘. 들어갈 내용:
- 거르기: 분야(인프라 · 보안 · AI), 수준(입문 · 초급 · 중급), 수강 방법(구독 포함 · 프리미엄 · 무료 공개), 정렬(최신순 · 인기순)
- 강의 8개: 강의 이름, 한 줄 소개, 강사, 분야 · 수준, 구성(장 수 · 실습 수), 가격 또는 구독 포함
- 조건에 맞는 강의가 없을 때의 화면도 하나
```

### 강의 상세

```
같은 방향으로 강의 상세 화면을 만들어 줘. "AI Agent 개발 · 초급" 강의. 들어갈 내용:
- 강의 이름, 한 줄 소개, 분야 · 수준, 강사
- 맛보기 영상 (무료 공개)
- 이 강의를 들으면 할 수 있게 되는 것 4~5개
- 목차: 6장, 장마다 절 목록과 실습. 일부 절은 "무료 공개"
- 실습 환경 소개: 제공하는 실습 서버에서 바로 따라 한다
- 실습 준비물 (예: LLM API 키)
- 강사 소개
- 가격, 구독자 할인가, 수강 기간, 환불 규정 요약
- 구매하기 / 구독으로 듣기 — 화면 어디에서든 쉽게 누를 수 있어야 함
- 자주 묻는 질문 3개
```

### 학습 화면 — 가장 중요

```
같은 방향으로 학습 화면을 만들어 줘. 이 서비스에서 가장 오래 머무는 화면이고, 교재를 길게 읽어도 편해야 해. 라이트 모드와 다크 모드 둘 다. 들어갈 내용:
- 지금 보는 강의 · 장 이름, 진도(%), 이전 · 다음, Q&A 열기, 다크 모드 전환
- 목차: "2장 LLM API와 HTTP" — 2.1 LLM API와 HTTP / 2.2 요청 만들기(지금 보는 곳) / 2.3 응답 읽기 / 2.4 messages와 role / 실습: 첫 API 요청 / 2.5 토큰과 사용료. 끝낸 절 표시.
- 장 맨 위 강의 영상
- 교재 본문: 절 제목 "2.2 요청 만들기", 문단 몇 개. 예: "LLM API 요청은 엔드포인트, 헤더, 본문 세 부분으로 이루어진다. 헤더에는 API 키를 넣어 누가 보낸 요청인지 알리고, 본문에는 모델 이름과 메시지를 JSON으로 담는다."
- 그림 1개와 설명 "그림 2-1. LLM API 호출의 층"
- 코드 예제 (파이썬 requests.post 5줄), 파일 이름, 복사 버튼
- 보충 설명 2개: "참고 — API 키는 .env 에서 읽고 Git에 올리지 않는다", "실무 — 제공사마다 엔드포인트와 모델 이름이 다르니 설정 파일 한 곳에 모은다"
- 실습: "실습 1 · 첫 API 요청", 실습 파일 내려받기, 스스로 확인 체크리스트 4개 중 3개 완료 (.env 에 API 키를 넣었다 / 상태 코드 200 을 받았다 / 응답에서 답 내용을 꺼내 출력했다 / 출력한 요청에 키 앞부분만 보인다)
```

### 로그인 · 회원가입

```
같은 방향으로 로그인 화면과 회원가입 화면을 만들어 줘.
- 로그인: Google 로 계속하기, 이메일 · 비밀번호, 비밀번호 찾기, 회원가입으로 가기. 입력이 틀렸을 때 모습도 하나.
- 회원가입: 이메일 · 비밀번호 · 닉네임, 약관 동의(필수 2개 · 선택 1개 · 전체 동의), 만 14세 이상 확인, 가입하기.
```

### 마이페이지

```
같은 방향으로 마이페이지를 만들어 줘. 들어갈 내용:
- 이어서 공부하기: 마지막에 보던 강의와 절, 진도
- 내 강의: 강의마다 진도, 실습 체크 수, 마지막 학습일, 이용 중 / 기간 만료
- 구독 상태: 이용 중 · 연간 구독 · 다음 결제일, 구독 관리
- 최근 결제 내역 3건: 날짜, 내용, 금액, 영수증
- 계정 설정으로 가기
```

### 모바일

```
같은 방향으로 홈, 강의 상세, 학습 화면을 휴대폰 화면으로 만들어 줘. 출퇴근길에 휴대폰으로 교재를 읽고 영상을 보는 사람이 많다. 학습 화면에서는 목차와 Q&A, 이전 · 다음에 쉽게 닿아야 하고, 긴 코드도 읽을 수 있어야 해.
```

## ③ 이어서 쓰는 말

디자인을 직접 지시하지 않고, 더 넓게 보거나 더 깊게 들어가게 하는 말이다.

| 하고 싶은 것 | 이렇게 |
|---|---|
| 방향을 더 보기 | `완전히 다른 방향으로 3가지 더 보여 줘. 앞의 3가지와 겹치지 않게.` |
| 더 과감하게 | `이 방향을 더 과감하게 밀어붙인 버전도 보여 줘.` |
| 두 방향 섞기 | `1번의 [마음에 드는 점]과 3번의 [마음에 드는 점]을 합쳐 줘.` |
| 이유 듣기 | `이 화면에서 디자인으로 가장 신경 쓴 점 3가지를 설명해 줘.` |
| 디자인 규칙 뽑기 | `지금 방향의 색, 글꼴, 간격, 부품 규칙을 디자인 시스템으로 정리해 줘.` |

마음에 드는 결과가 나오면 마지막 줄(디자인 시스템 정리)까지 받아 두세요. 개발에 옮길 때와 디자이너에게 보낼 때 그대로 쓸 수 있습니다.
