# 사이트 구조와 화면 목록 (v0.3 초안)

- 작성: 2026-11-03 / v0.2: 여러 강사 구조, 가입 방식, 강의 Q&A / v0.3: 결정 질문 모두 정리, 9장 정산 정책
- 상태: 초안. **⚠️ 결정 필요** 표시가 있는 곳은 운영자 결정 후 고친다.
- 기준이 되는 결정: B2C(개인), 단건 구매 + 구독, **여러 강사가 강의를 올림**, 퀴즈·평가 없음, 실습은 스스로 확인(체크), 교재는 업로드 패키지(`교재_업로드_패키지_규격.md`), 영상은 대부분 유튜브 공개 + 일부 챕터만 자체 서버(암호화 HLS + 워터마크), 첫 강의는 AI Agent 개발 초급.

## 1. 사용자 유형

| 유형 | 설명 | 볼 수 있는 것 |
|---|---|---|
| 방문자 | 로그인하지 않은 사람 | 공개 페이지, 강의 소개, 유튜브 공개 영상, 무료 미리보기 |
| 회원 | 가입했지만 수강권이 없음 | + 마이페이지, 무료 강의 수강 |
| 수강생 | 단건 구매한 수강권이 있음 | + 구매한 강의 학습, 그 강의 Q&A |
| 구독자 | 구독 중 | + 구독 대상 강의 전체 학습, 프리미엄 강의 할인 구매 |
| **강사** | 강의를 올리고 판매 수익을 나눠 받는 사람 | + 강사 화면: 내 강의 관리, Q&A 답변, 판매·수강 현황, 정산 내역 |
| 운영자 | 플랫폼을 운영하는 사람 (지금은 나) | + 관리자 화면 전체. 강사 승인, 강의 검수·공개, 정산 확정 |

- 한 사람이 여러 유형일 수 있다 (운영자이면서 강사, 강사이면서 다른 강의의 수강생). 화면은 "유형"이 아니라 **가진 수강권과 권한**으로 판단한다.
- 강사는 **자기 강의에 관한 것만** 본다. 수강생 개인정보(이메일, 이름, 결제 정보)는 강사에게 보여주지 않는다. Q&A 에서는 닉네임만 보인다. (개인정보 제3자 제공을 피하기 위해)

## 2. 사이트맵

```text
[공개]
├─ 홈
├─ 강의
│   ├─ 강의 목록 (분야: 인프라 · 보안 · AI / 강사별)
│   └─ 강의 상세 ── 무료 미리보기, 유튜브 공개 영상
├─ 강사 소개 (강사별 페이지: 소개, 강의 목록)
├─ 구독 안내 (요금제)
├─ 강사 지원 (강의를 올리고 싶은 사람)
├─ 공지사항
├─ 자주 묻는 질문
└─ 정책: 이용약관 · 개인정보처리방침 · 환불 정책 · 강사 이용약관

[회원]
├─ 회원가입 · 로그인 (이메일 · 구글 · 카카오) · 이메일 인증 · 비밀번호 재설정
├─ 결제: 주문서 ➔ 결제(토스페이먼츠) ➔ 결제 완료
├─ 내 강의실
│   └─ 학습 화면 (영상 ➔ 교재, 강의 Q&A)
└─ 마이페이지
    ├─ 내 정보 · 로그인 연결(구글·카카오) · 알림 설정 · 회원 탈퇴
    ├─ 수강권 (만료일 · 연장)
    ├─ 구독 관리 (해지 예약 · 즉시 해지/환불 요청 · 결제 수단 변경)
    ├─ 결제 내역 · 영수증 · 환불 요청
    ├─ 내 질문 (강의 Q&A)
    └─ 1:1 문의

[강사]
├─ 강사 대시보드
├─ 내 강의: 교재 패키지 업로드 · 영상 연결 · 미리보기 · 검수 요청
├─ 강의 Q&A 답변
├─ 판매 · 수강 현황 (수강생 수, 진도 분포, 매출. 개인 식별 정보 없음)
├─ 정산 내역 · 정산 정보 등록
└─ 강사 프로필

[관리자 (운영자)]
├─ 대시보드
├─ 강사: 지원 심사 · 승인 · 계약 조건(수익 비율) · 정지
├─ 콘텐츠: 과정 · 교재 패키지 · 버전 · 영상 · 미리보기 · **검수 후 공개**
├─ 판매: 상품(단건 · 구독 플랜) · 가격 · 구독자 할인
├─ 회원 · 수강권 (수동 발급 · 기간 조정)
├─ 주문 · 결제 · 환불 처리 · 구독
├─ 정산: 월별 계산 · 확정 · 지급 기록
├─ 운영: 공지 · 자주 묻는 질문 · 1:1 문의 · Q&A 관리(신고 · 숨김)
└─ 기록: 메일 발송 · 관리자 작업 기록(감사 로그)
```

## 3. 콘텐츠 구조 (강의 안의 구조)

```text
강사 (Instructor)
└─ 과정 (Course)          예: AI Agent 개발 · 초급     ← 교재 패키지의 course_id
    └─ 챕터 (Chapter)      예: CHAPTER 2. LLM API 호출   ← chapter_id
        ├─ 챕터 영상        맨 위에 하나 (없어도 됨)
        ├─ 교재 본문        업로드 패키지의 content.html. 챕터 영상 아래에 이어진다
        │   ├─ 끼운 영상     교재 사이사이의 실습 시연 · 추가 설명 영상 (교재의 "영상 자리")
        │   └─ 실습 Section  교재 안의 "실습 N" Section
        │       ├─ 실습 영상   예: ch02_lab01 (mp4 + 자막 srt). 끼운 영상의 하나
        │       └─ 스스로 확인 평가 기준 체크 목록 (manifest 의 self_check)
        ├─ 첨부 자료        예: 실습파일/code/ch02_lab1_step1 (zip 다운로드)
        └─ Q&A             이 챕터에 달린 질문 · 답변
```

- 과정마다 **소유 강사**가 한 명 있다. (공동 강사는 3단계)
- 강사가 올린 강의는 **운영자 검수를 거쳐야 공개**된다. 교재를 고친 새 버전도 같다.

**영상 규칙** (유튜브 API 정책 III.F.3: 사이트에 넣은 유튜브 영상을 보는 대가로 돈을 받으면 안 된다)
- 유튜브 영상은 유튜브에 **공개**로 올리고, 사이트에서도 **로그인·결제 없이** 재생되게 한다. 커리큘럼에 "무료 공개" 표시를 붙이고 강의 상세에서 바로 볼 수 있다.
- 자체 서버 영상(암호화 HLS + 워터마크)만 수강권이 있어야 재생된다.
- 유료 과정의 가치 = 교재 본문 + 유료 전용 챕터 영상 + 실습 파일 + 스스로 확인 + 강의 Q&A + 진도 관리.

**진도율** = 챕터마다 (교재를 끝까지 읽음 + 영상을 90% 이상 봄 + 실습 체크 항목을 모두 체크) 를 합산. 평가가 없으므로 "수료"는 진도율 100%로만 정한다. (수료증 발급은 2단계)

## 7. 첫 강의(AI Agent 개발 초급) 때문에 필요한 것

- **실습 준비 안내**: 수강생이 자기 LLM API 키를 만들어 `.env` 에 넣는다. 강의 상세(P-03)에 "준비물: API 키, 사용 요금은 본인 부담"을 분명히 쓰고, 첫 챕터에 키 발급 안내를 둔다. 키를 화면이나 **Q&A 에 붙여 넣지 않도록** 안내하고, Q&A 입력 화면에서 키 형식(예: `sk-...`)을 발견하면 경고한다.
- **실습 영상**: 실습마다 mp4 + 자막(srt) 이 있다 (`2_교재/실습영상`). 플랫폼은 자막을 WebVTT 로 바꿔 함께 재생한다. 영상은 영상 자리 key(`ch01_lab01`)에 연결한다.
- **실습 파일**: **챕터별 첨부로 나눠 준다** (2026-11-03 결정). `실습파일/code/ch02_lab1_step1` 처럼 챕터에 속한 폴더는 그 챕터의 첨부(zip)로, `.env.example` · `check_setup.py` 처럼 과정 전체에 필요한 파일은 첫 챕터(또는 "준비" 챕터)의 첨부로 둔다. 받은 기록은 `attachment_downloads` 에 남긴다 (환불 판단 근거).

## 8. 여러 강사 구조 때문에 챙길 법 · 제도

- **강사 이용약관**: 수익 배분, 정산, 콘텐츠 저작권(강사 소유, 플랫폼은 이용 허락), 검수 · 게시 중단 사유, 계약 종료 후 기존 수강생의 수강 보장.
- **강사 정산 정보**: 개인 강사의 원천징수에는 주민등록번호가 필요하다. 고유식별정보이므로 암호화 저장, 접근 권한 최소화, 접근 기록을 남긴다. 사업자 강사는 사업자등록번호와 세금계산서.
- **수강생 개인정보**: 강사에게 넘기지 않는다 (닉네임과 통계만). 넘겨야 하는 일이 생기면 제3자 제공 동의가 필요하다.
- **카카오 로그인**: 카카오에서 이메일을 받으려면 비즈 앱 전환(사업자 정보 등록)이 필요하다. 테스트 기간에는 개인 개발자 앱으로 이메일 없이 시험하고, 실오픈 때 전환한다.

## 9. 정산 정책 (v0.1, 기본값)

> 모든 비율 · 방식 · 상한은 **정책 버전**으로 관리한다. 운영자가 AD-16 에서 새 버전을 시행일과 함께 등록하면, **시행일 이후의 매출부터** 새 정책이 적용된다. 이미 확정된 정산은 바뀌지 않는다. 정산마다 "어떤 정책 버전으로 계산했는지"를 기록한다. 강사에게 불리한 변경은 강사 이용약관에 정한 기간(예: 30일) 전에 알린다.
>
> 세금 처리(부가세, 원천징수, 세금계산서)는 기준 설계안이다. 실오픈 전에 세무사 확인을 받는다.

### 9.1 단건 매출 (단건 강의, 패키지, 연장권)

```text
정산 기준액 = 실제 결제 금액 − 부가세 − 결제 수수료(PG)
강사 몫     = 정산 기준액 × 강사 비율
```

| 항목 | 기본값 | 바꿀 수 있는 단위 |
|---|---|---|
| 강사 비율 | **60%** | 강사별 계약, 과정별 예외 |
| 구독자 할인으로 판 경우 | 실제 결제 금액 기준 (할인은 플랫폼과 강사가 같은 비율로 부담) | 정책 버전 |
| 패키지(여러 강사 강의 묶음) | 각 강의 정가 비율로 결제 금액을 나눈 뒤 위 계산 | 정책 버전 |

### 9.2 구독 매출

```text
이번 달 구독 기준액 = 이번 달 구독 매출 − 부가세 − 결제 수수료 − 환불
                     (연간 구독은 결제 금액을 12개월로 나눠 달마다 반영)
강사 배분 풀        = 구독 기준액 × 강사 풀 비율
과정별 배분액       = 강사 배분 풀 × (그 과정의 유효 학습 시간 ÷ 구독 포함 과정 전체의 유효 학습 시간)
```

| 항목 | 기본값 | 이유 |
|---|---|---|
| 강사 풀 비율 | **50%** | 구독은 플랫폼의 모객 · 결제 · 운영 비중이 단건보다 크다 |
| 배분 방식 | **유효 학습 시간 비례** | 수강생이 실제로 시간을 쓴 강의에 돌아간다. 진도 비례는 짧은 강의가, 균등 배분은 강의 수가 많은 강사가 유리해진다 |
| 대상 | 구독 포함 과정만 (프리미엄 단건 전용 과정 제외) | |

**유효 학습 시간** (부정 방지 규칙. 모두 정책 버전으로 바꿀 수 있다)

| 규칙 | 기본값 |
|---|---|
| 영상 | 실제로 재생된 구간만. 같은 구간을 다시 본 것은 하루 1번만 센다. 배속은 콘텐츠 시간 기준 (2배속으로 10분 영상을 다 보면 10분) |
| 교재 | 화면이 보이고(탭 활성) 스크롤 · 클릭 활동이 있는 동안만. 활동이 2분 없으면 멈춘다 |
| 상한 | 수강생 1명 · 과정 1개 · 하루 **3시간**까지 |
| 유튜브 공개 영상 | 센다 (구독자가 과정 안에서 본 경우만) |
| 제외 | 그 과정 강사 본인과 운영자의 학습 시간 |

### 9.3 환불

- 정산 확정 **전**의 환불: 그 달 매출에서 뺀다.
- 정산 확정 **후**의 환불: 다음 달 정산에서 그 강사 몫만큼 뺀다. 다음 달 지급액이 마이너스이면 그다음 달로 넘긴다.
